# CLAUDE.md – verkodo

Rules for working in this repository. This file is public: nothing personal goes here.

## What this is

verkodo – truth code – mathematics and law written formally, checked by machine. A falkOSS project.
Scope: the language and its tools – reading `.vk` files, the knowledge layer (concepts with variants and bridges,
theorems, paths, labels per language, sources), export to Lean 4 and Lean's verdict back as diagnostics, a small typed
rule language for law (norms with inputs, constants, rules and exceptions), and rendering to text, PDF and HTML with
hover explanations derived from the formalisation. The language: `docs/language.md` (draft). The code comes from the
prototype `formwelt` (same licence, same authors). Done: M0 parser and `check`, M1 knowledge graph and HTML with
nested hover, M2 the Lean bridge, M2b names back from Lean's info trees (`crates/verkodo-lean/src/names.lean`), law
in Lean (norms as Lean functions, properties as theorems), M3 a path as a Typst PDF (`verkodo pdf`), M4 the
language server (`verkodo lsp`, docs/editors.md), the language questions of the draft, a web editor (prototype),
the data types of the legal profile (enumerations, units, records and lists, tables, dates, norms that use norms).
Next: OPEN.

## Layout

| Path | What |
|---|---|
| `crates/verkodo-syntax` | lexer, parser, syntax tree, diagnostics of the language |
| `crates/verkodo-core` | the domain, no I/O: stable ids, knowledge graph, references (also inside Lean formulas), types of the legal profile, checks of paths, versions, translations, exact evaluation of norms |
| `crates/verkodo-lean` | export to Lean 4, checked by `names.lean` through `lake env lean --run`; Lean's messages and resolved names back onto the `.vk` source |
| `crates/verkodo-render` | one content, each format a feature: `html` (pages with nested hover cards and Lean's verdict), `typst` (a path as a document for PDF: links and an appendix instead of hover), `markdown` (hover in editors); LaTeX planned |
| `crates/verkodo-lsp` | the language server: LSP over stdio with lsp-server, the protocol's types as JSON; Lean on save in a thread |
| `crates/verkodo-wasm` | verkodo in the browser for the web editor: core and renderer compiled to WebAssembly, JSON through a buffer, no wasm-bindgen; the only crate that may use `unsafe` – for `#[unsafe(no_mangle)]` on its exports |
| `crates/verkodo-sdk` | the SDK: every command and query (reading files, Lean, rendering, formatting, hover: `knowledge`); the **only** layer the interfaces – and IDEs – use |
| `crates/verkodo-api` | HTTP/JSON with axum, described in OpenAPI by utoipa: `GET /api/v1/lean`, `POST /api/v1/prove` (Lean for the web editor when `serve --lean <dir>`) |
| `crates/verkodo-web` | the web editor, built by `pnpm build` into `crates/verkodo-web/web` (ignored by git, part of the crate) and served around the API: CSP with a nonce per page |
| `crates/verkodo` | the command line: `check`, `graph`, `prove`, `render`, `pdf`, `fmt`, `eval`, `translations`, `lsp`, `serve`, `openapi` |
| `examples/` | example knowledge: a slice of Analysis I (with a French translation), a simplified § 19 UStG, the scale of § 32a EStG (CC BY 4.0) |
| `lean/` | the Lean project (Lean 4, Mathlib, pinned); `lake exe cache get` there once; generated files in `lean/generated/` |
| `web/` | the web app: the editor (CodeMirror 6, verkodo as WebAssembly – `pnpm wasm` builds it); Vite, Svelte 5, TypeScript; types from `api/openapi.json` (openapi-typescript, openapi-fetch); `pnpm build:pages` builds it static, without Lean, for verkodo.github.io/verkodo/editor/ (`.github/workflows/pages.yml`) |
| `editors/vscode` | the VS Code extension: a TextMate grammar and a client for `verkodo lsp` (vscode-languageclient), bundled with esbuild; `pnpm test` tokenizes as VS Code does |
| `api/openapi.json` | generated by `verkodo openapi`; CI checks it matches the code |
| `docs/` | the documentation – Jekyll, Just the Docs, published by GitHub Actions at verkodo.github.io/verkodo (verkodo.dev once registered) |

## Principles

- **Everything included:** one edition, every feature free; no paid tiers, licence keys or unlocks.
- **No telemetry.** Only connections that are technically needed or that users start themselves.
- **One SDK, many interfaces:** CLI, LSP and API go through `verkodo-sdk`; the web app and IDEs only through the
  API, which is also the licence boundary for apps under other licences.

## Licences

- Everything here: **AGPL-3.0-or-later**, an SPDX header in every own source file; REUSE checked in CI.
- `examples/`: the content under **CC BY 4.0**, named in each file's header.
- `docs/assets/` and `web/public/favicon.svg` are copies from `verkodo/brand` under CC BY-ND 4.0 – update them by copying, never edit them here.
- Code taken over from elsewhere keeps its licence and names its origin.

## Rules

- English in code, docs and commits; commits signed off (`git commit -s`).
- No personal data in tracked files (names, paths like `/Users/…`, hostnames, keys).
- Claims need a source; unverified statements are marked **OPEN**.
- No externally loaded fonts or scripts in anything web-based.
- Dependencies at least 14 days old: ranges in `Cargo.toml`, exact in `Cargo.lock` and `package.json`
  (CONTRIBUTING.md); every crate but `verkodo-wasm` goes to crates.io from a tag `v*`; Rust edition 2024, the toolchain in
  `rust-toolchain.toml`; TypeScript 6 until Svelte supports 7, Node 26, pnpm.
- After changing the API: `cargo run -q -- openapi > api/openapi.json` and `pnpm --dir web api`.

## Checks

```sh
cargo fmt --check && cargo clippy --all-targets && cargo test && cargo deny check
cargo run -q -- prove examples   # Lean: 62 checked, 2 open (one proof missing on purpose), 0 rejected
(cd web && pnpm wasm && pnpm check && pnpm build)   # pnpm wasm needs rustup's cargo (target from rust-toolchain.toml)
```
